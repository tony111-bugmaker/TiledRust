## 一、先分清两个东西：地形集 vs 自动地图

Tiled 里有两套「自动选过渡瓦片」的功能，长得像但机制完全不同。别混。

| | 地形集 Terrain Sets | 自动地图 AutoMapping ← **铁锈用的** |
|---|---|---|
| 原理 | 给每个瓦片的**四个角**标注地形类型，用专门的「地形笔刷」画时按角匹配 | 用一组**外部规则图（.tmx）**定义「输入图案 → 输出图案」，按层上的格子匹配 |
| 配置存哪 | 图块集内部 `<terraintypes>`，跟 tileset 绑死 | 独立 rules.txt + 若干规则图 .tmx |
| 用法 | 切到地形笔刷 / 地形填充模式 | 绘制时实时重算，或 Ctrl+M 对整图跑一遍 |
| 能力 | 只管地形边界过渡 | 多格输入/输出、多输出变体、删旧瓦片，通用 |
| 铁锈用得上吗 | ❌ 用不上 | ✅ 官方标准做法 |

**为什么地形集用不上**：`terraintypes` 只是 Tiled 编辑器侧的元数据，RW 游戏读的是图层里的 gid，根本不读这个定义；而且铁锈的草/水/沙过渡，官方已经用 ruleset 规则图全部覆盖了。所以你在 Tiled 里看到「没有可用的地形集」可以直接无视。

## 二、铁锈官方规则是怎么组织的（实测）

### 2.1 目录结构

```
<游戏目录1.15>/mods/maps/
├── rules.txt                  ← 总索引（3 行）
└── rules/
    ├── rules.txt              ← 空文件（历史遗留，不用管）
    ├── ruleset1.tmx           ← 主过渡规则（最大的一张）
    ├── ruleset2.tmx           ← 装饰 / 多变体规则
    ├── ruleset3.tmx           ← 输出区域大于输入区域的规则
    └── ruleset1_snow out.tmx  ← 老式命名的样例，未被索引引用
```

顶层 `mods/maps/rules.txt` 全文就 3 行：

```
./rules/ruleset1.tmx
./rules/ruleset2.tmx
./rules/ruleset3.tmx
```

每行一个规则图路径，**相对 rules.txt 所在目录**解析。`#` 和 `//` 开头是注释。

### 2.2 三张规则图的分工（实测层结构）

| 规则图 | 尺寸 | 地图属性 | 图层（层名即语义） |
|---|---|---|---|
| **ruleset1.tmx** | 103×55 | `AutomappingRadius=2`、`DeleteTiles=1` | `output_Ground`、`output_Items`、`input_set`、`regions` |
| **ruleset2.tmx** | 40×40 | — | `output1_Ground`、`output2_Ground`、`output3_Ground`、`input_set`、`input_set_decoration`、`inputnot_set_decoration`、`regions` |
| **ruleset3.tmx** | 40×40 | — | `output_Ground`、`output_Items`、`input_set`、`regions_input`、`regions_output` |
| ruleset1_snow out.tmx | 60×40 | `AutomappingRadius=2`、`DeleteTiles=1` | `ruleRegions`、`ruleSet`、`rule_Ground`（老式命名，未被引用） |

三张图各有侧重：
- **ruleset1**：主力。基本地形两两交界（草↔水、雪↔山、沙↔水…）的直边、拐角、内外角，输出写 `Ground`/`Items`。
- **ruleset2**：带 `output1/2/3_Ground` 三个随机变体，还涉及 `set_decoration` 装饰层，用 `inputnot` 做排除条件。
- **ruleset3**：用 `regions_input` + `regions_output` 分离输入/输出区域，实现「小输入 → 大输出」（如 1×1 输入生成 3×3）。

### 2.3 层名约定（解析器实际识别的写法）

| 层名模式 | 含义 | 例子 |
|---|---|---|
| `regions` | 规则区域；**一个 4-邻接连通块 = 一条规则** | `regions` |
| `regions_input` / `regions_output` | 分别定义输入区域、输出区域（输出可更大） | ruleset3 |
| `input_<层名>` | 输入条件：该坐标该层必须是指定瓦片 | `input_set` |
| `inputnot_<层名>` | 排除条件：该坐标该层不能是指定瓦片 | `inputnot_set_decoration` |
| `input<index>_<层名>` | 同一位置多个并列输入条件 | — |
| `output_<层名>` | 输出：匹配成功后写什么 | `output_Ground` |
| `output<index>_<层名>` | 输出的随机变体，index 从 1 起 | `output2_Ground` |
| `ruleRegions`/`ruleSet`/`rule_<层名>` | 老式命名（Tiled 1.9 之前），也能识别 | snow out |

> **注意**：`input_` 后面第一个 `_` 之后的**整个字符串**才是目标层名。所以 `input_set_decoration` 检查的是 `set_decoration` 层，不是 `set` 层。工作地图没有这一层时按全空层处理，这条规则就不会误匹配。

### 2.4 地图属性

| 属性 | 作用 |
|---|---|
| `DeleteTiles=1` | 写入前先清掉区域内的旧过渡瓦片。本项目用「按 set 层基础地形重建」代替粗暴清空，既清旧瓦片又不留空洞。 |
| `AutomappingRadius=2` | 绘制时（实时）重算范围 = 改动格 ± N。官方为 2。 |

### 2.5 解析结果（用项目 AutoMapper 实测）

```
已加载 274 条规则（3 个规则图）
输出层分布：Ground 274 条 / Items 14 条
输入层：几乎全部落在 set 层（标记层）
```

也就是说：官方 274 条规则，本质都是「**看 set 层画了什么基础地形 → 在 Ground/Items 层自动生成对应过渡瓦片和装饰物**」。

### 2.6 基础地形 gid ↔ 地形对照（实测 + 软件口径）

这些是 set 层里当「标记」用的地形首格。规则匹配前，任意同图集瓦片会被归一到首格：

| gid | 地形 | gid | 地形 |
|---|---|---|---|
| 1 | 山 Mountain | 770 | 沙 Sand |
| 36 | 雪 Snow | 192 | 水 Water |
| 116 | 冰 Ice | 193 | 深水 Deep Water |
| 126 | 草 Long Grass | 176 | 土 |
| 186 | 浅水 Shallow Water | 945 / 978 | 其它基础地形 |

> 名字里带 `" - "` 的图集（如 `ShallowWater Water - Flat`、`Ice Ice - Flat`）是**过渡图集**，不作为基础地形，归一逻辑会跳过它们。这是写自定义规则时最容易踩的坑之一。

## 三、一条规则到底怎么匹配

理解这四点，就能看懂 ruleset 图，也能自己写：

1. **区域 = 连通块，不是外接矩形**。`regions` 层上一个 4-连通的非空格子集合就是一条规则。官方拐角规则大量是 2×2 缺一角的 L 形——缺口那格**不属于**规则，不能参与匹配。早期按外接矩形补齐会让草/水拐角永远匹配不上。

2. **输入条件**：`input_set` 在区域各坐标上标了某地形 gid，表示「这里必须是这种地形」。空 input 格在旧式规则里是**通配**——但要求「非空且不等于本规则用过的任何 gid」，否则 2×2 规则会在纯草地内部乱匹配。

3. **输出**：`output_Ground` 标的是「匹配成功后往 Ground 层写什么」。多个 `outputN` 是随机变体，本项目固定取第一套保证可复现。

4. **顺序消冲突**：多条规则可能写同一格，按 rules.txt / 规则图里的固定顺序，后面的覆盖前面的。ruleset 开头几条「填充区域」的规则就是给后面的细节规则打底。

## 四、在你的软件里导入自定义规则

### 4.1 操作步骤

1. 顶部菜单 **「地图」→「添加 Automapping 规则文件…」**
2. 文件框里选你的 **`rules.txt`**（默认起点是 `mods_maps/rules.txt`）
3. 状态栏出现「已加载 N 条自动映射规则（M 个规则图）」即成功；如果缺文件会列在错误信息里
4. 勾上 **「绘制时自动地图」** 开始实时自动映射；或按 **Ctrl+M** 手动对整图跑一遍

> ⚠️ **顺序很重要**：手动导入的规则会**整体替换**当前加载的规则（不是追加）。而且勾选「绘制时自动地图」时如果还没加载过规则，会自动去读默认的 `mods_maps/rules.txt` 把你的覆盖掉。所以一定**先导入自己的 rules.txt，再勾选开关**。

### 4.2 相关功能入口（代码位置，方便你核对）

| 功能 | 菜单/快捷键 | 代码 |
|---|---|---|
| 导入自定义 rules.txt | 地图 → 添加 Automapping 规则文件… | `main_window.py:360-361`, `_pick_rules_file()` at `:3713` |
| 加载规则（内部） | — | `_load_automap_rules()` at `:3700` → `AutoMapper.load()` |
| 绘制时自动地图（实时） | 地图 → 绘制时自动地图（勾选） | `act_automap_while` at `:365`, `_toggle_automap()` at `:3724` |
| 手动全图自动映射 | 地图 → 自动映射 / Ctrl+M | `act_automap_now` at `:362`, `_run_automap()` at `:3760` |
| 规则索引解析 | — | `rwmap/rw/automapping.py` `AutoMapper.load()` at `:212` |

### 4.3 想改默认规则源

默认从 `profile.mods_maps / rules.txt` 读（1.15 配置在 `config/profiles/rw115.json` 的 `mods_maps` 字段）。两种改法：
- **临时**：用菜单导入，仅当前会话生效；
- **长期**：把你自己的 rules.txt 和规则图放进一个目录，改 profile 的 `mods_maps` 指向它（注意这会影响保存/导出路径，谨慎）。

## 五、从零写一条自己的规则

以「给草↔水边界生成过渡瓦片」为例，用 Tiled 做规则图（你机器上 `<Tiled目录>\tiled.exe` 就有）：

1. **建规则图**：在 Tiled 新建一个和地形图同 tile size（20×20）的地图，尺寸不用大，能放下几组图案即可。

2. **建图层**（名字严格按约定）：
   - `regions` —— 画一个 4-连通的色块圈出规则区域（比如 2×2 的 L 形）
   - `input_set` —— 在区域各格标上输入地形：草地首格 126、水 186
   - `output_Ground` —— 在对应位置画上你要的过渡瓦片 gid

3. **设地图属性**（Custom Properties）：
   - `DeleteTiles` = `1`（写前清旧）
   - `AutomappingRadius` = `2`

4. **存档**：比如 `my_rules/transition.tmx`。

5. **建索引**：在 `my_rules/rules.txt` 里写：
   ```
   ./transition.tmx
   ```

6. **导入验证**：软件里走 [4.1 的步骤](#41-操作步骤) 选 `my_rules/rules.txt`，看状态栏规则数是否符合预期；再开「绘制时自动地图」在测试图上画草水边界验证效果。

> 抄作业最快的路径：直接复制 `<游戏目录1.15>/mods/maps/rules/ruleset1.tmx`，在 Tiled 里打开，照着现有的 `regions`/`input_set`/`output_Ground` 图案改，删掉不需要的连通块。gid 一定是**你地图实际图集里的 gid**，别照搬数字。

## 六、坑与注意事项

1. **gid 必须对齐实际图集**。规则图里的瓦片 gid 要来自工作地图用的图集；set 层标记会被归一到各图集首格，用中间某一格（如 Long Grass 的 130）写进 set 层不会匹配任何规则——归一化逻辑会把它拉回首格 126。

2. **过渡图集名不能含 `" - "`**。带这个符号的被当过渡图集跳过，不作为基础地形。

3. **路径相对 rules.txt**。换目录放规则时，索引里每行路径要跟着改（`.resolve()` 是按索引文件所在目录解析的）。

4. **区域是连通块不是矩形**。L 形规则的缺口格千万别当成规则的一部分去补。

5. **空 input 格的通配条件**。没有 `inputnot` 层时，区域里所有 input 层都为空的坐标仍要求「非空且不等于本规则用过的任何 gid」——漏掉这条，规则会在纯色区域乱触发。

6. **`input_set_decoration` 查的是 `set_decoration` 层**，不是 `set`。工作地图没这层就按全空处理，规则不会误匹配——这是官方有意为之。

7. **`outputN` 变体本项目只取第一套**，结果可复现，但也意味着随机变体效果在这里看不到。

8. **手动导入会覆盖默认**。再次强调：先导入、后勾选。

## 七、常见问题

**Q：我导入后状态栏报「缺规则文件 xxx」？**
A：rules.txt 里那行路径相对索引文件解析，检查规则图是否真在那个位置、文件名大小写是否一致。

**Q：规则数加载出来了，但画图没反应？**
A：① 检查有没有先勾选「绘制时自动地图」或按 Ctrl+M；② 落笔的地形 gid 是不是基础地形首格；③ 当前层是不是 set 层（实时模式固定写 set 层）；④ 规则里的 input gid 和你地图图集的 gid 对不对得上。

**Q：过渡瓦片生成在错误的图层？**
A：看规则的 `output_<层名>` 后缀，`output_Ground` 写 Ground，`output_Items` 写 Items。层名映射见 `automapping.py` 的 `_output_target()`。

**Q：能不能不改官方资产、自己加一套地形过渡？**
A：能。把你自己的 rules.txt + 规则图放独立目录，用菜单导入即可，不动 `<游戏目录1.15>`。想长期用就改 profile 的 `mods_maps`。

**Q：地形集到底要不要学？**
A：不用。RW 生态不走 terraintypes，你的软件也没有地形笔刷。把精力放在 ruleset 规则图上。

## 八、照搬 Tiled 官方语义（2026-11-19）

按 Tiled 官方文档（automapping.rst）与 C++ 源码（`src/tiled/automapper.cpp`）
把规则处理语义补齐。核心原则：**官方三张规则图一个都没用到这些新特性，
所以全部是增量，100% 复现率与实时绘制行为保持不变**。

| 特性 | 来源 | 本实现 | 官方图影响 |
|---|---|---|---|
| rules.txt 嵌套 `.txt` | Tiled 文档 | `_load_rules_txt()` 递归解析，循环引用/深度保护 | 无（入口只列 3 个 tmx） |
| `[glob]` 文件名过滤器 | Tiled 1.9+ | `AutoMapper.target_map_name` 设当前地图名后按过滤器裁剪 | 无（未设=不过滤） |
| tile `MatchType` 属性 | Tiled 源码枚举 | Empty/NonEmpty/Other/Negate/Ignore → any_of/none_of/ignore/negate | 无（官方图无此属性） |
| `StrictEmpty` / `AutoEmpty` | 图层属性 | `_layer_bool_prop()` | 无 |
| `Ignore*Flip` | 图层属性 | `_layer_flip_mask()`，比较 gid 时按位掩码 | 无 |
| `MatchOutsideMap` / `OverflowBorder` / `WrapBorder` | Tiled 1.3+ | `Rule.border`，`_read_at()` 越界策略（Wrap>Overflow>Outside） | 无 |
| `NoOverlappingRules` | Tiled 1.9+ | `Rule.no_overlapping`，输出区重叠则跳过 | 无 |
| `MatchInOrder` | Tiled 向后兼容 | 有显式 regions 层时**默认 True**（照搬）；gid 索引优化后性能与并发模式相当（6 vs 5 ms） | 开/关均 100% 复现 |
| 随机输出 `output1/2/3` | Tiled `RandomPicker` | `AutoMapper.random_variants`（**默认 False 保复现**）+ `random_seed` 确定性选择 + `probability` 权重 | 无（默认取 variant0） |
| RuleOptions（Probability/ModX/ModY/OffsetX/OffsetY/Disabled/IgnoreLock） | Tiled 源码 | `Rule` 字段，`_apply_rule()` 应用 | 无（均默认值） |
| 空输出 cell 不覆盖 / `MatchType::Empty` 显式写空 | Tiled `copyTileRegion` | 普通空输出跳过，`explicit_empty_outputs` 写 0 | 无 |

**验证**：全量 780 例通过（原 772 + 新增 8）；官方示例图 Ground 复现率
**100.0000%（25600/25600）**；局部实时重算与全图重建逐格一致。

**取舍说明**：随机输出在 Tiled 里是默认行为，但会破坏你此前刻意做到的
100% 可复现结果（ruleset2 的 3 套输出 gid 完全不同）。因此照搬了完整实现，
但默认关闭；需要 Tiled 式随机时设 `mapper.random_variants = True`
（`random_seed=None` 为真随机，整数则为可复现随机）。

## 九、gid 空间投影（真实地图图集布局与规则图不同的根治）

官方示例图的图集 firstgid 与规则图**完全一致**，所以之前的 100% 复现率掩盖了一个
架构级 bug：引擎拿规则图的**绝对 gid** 直接去工作地图匹配和输出。真实地图
（如 `[z;p10]Large Lava Divide`）的图集布局不同，就会出错。

**典型故障（录屏里的"黑色獠牙"）**：工作图 Lava 图集首格是 941、标记 945（Lava+4），
而规则图 Lava 首格 974、标记 978，Stone 标记恰好也是 945。用户画岩浆选中 Lava+4
（gid 945）时，旧引擎把它当成规则图的 **Stone 标记**，触发 Stone↔Lava 过渡，
输出规则图 gid 989–1003（Stone Lava-Ridge）；但工作图这段 gid 属于
LongGrass Ridge 图集，于是显示成一整排黑色獠牙。

**修复**：`AutoMapper._project_rules()` 在 compute 时按「图集名 + 图集内相对索引」
