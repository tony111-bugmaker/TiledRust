# 生存模式完整模板

本模板说明如何用本编辑器做一张能进游戏正常玩的生存图。核心是**四层配置**，
缺任何一层都可能出现"不刷兵 / 兵站着不动 / 没有倒计时 / 游戏打不开"的问题。

| 层 | 对象 | 作用 | 缺失后果 |
|---|---|---|---|
| ① 模式开关 | `map_info` | 告诉游戏这是生存图、怎么判胜负、波次表是什么 | 游戏按遭遇战处理，没有官方倒计时 |
| ② 敌方 AI | `team_1_info` | 让敌人主动进攻 | **刷出来的兵站着不动或游荡** |
| ③ 出兵点 | `attack_point` | 决定官方波次的兵从哪冒出来 | 兵从地图边缘随机刷出，位置不可控 |
| ④ 波次编排 | 波次生成器 / 官方波次表 / unitAdd | 决定每波什么时候刷、刷什么 | 没兵可刷 |

下面按这个顺序讲，最后给参数速查和常见坑。

---

## ① 地图模式与胜负条件（map_info）

在节点图里选中 `map_info` 对象（名字就是 `map_info`，type 可以为空），
右侧属性面板改这几项：

| 属性 | 推荐值 | 说明 |
|---|---|---|
| `type` | `survival` | 地图模式。生存图必须是这个值 |
| `winCondition` | `allUnitsAndBuildings` 或 `none` | 胜利判定，详见下文 |
| `loseCondition` | `commandCenter` 或 `allUnitsAndBuildings` | 失败判定，详见下文 |
| `survivalWaves` | **不要手填** | 用本编辑器的波次生成器自动写；手填格式错了游戏可能加载异常 |
| `introText` | 开局简报文字 | `\n` 换行 |
| `fog` | `los` / `map` / `NONE` | 战争迷雾 |

### 判定结束规则能写什么（重要）

我把游戏 `game-lib.jar` 里的 `TriggerEngine` / `ObjectiveType` / `TriggerType`
都翻过了，结论是：

- 游戏的胜负判定是 **7 个固定枚举值**，引擎每帧检查，
  不是可以由触发器动态设置的变量：

  | 值 | 含义 | 适用 |
  |---|---|---|
  | `none` | 不判定（用于无尽生存） | 没有终点的图 |
  | `commandCenter` | 消灭对方指挥中心 | 常规推家图 |
  | `mainBuildings` | 消灭对方主要建筑 | 常规推家图 |
  | `allBuildings` | 消灭对方全部建筑 | 全歼图 |
  | `allUnitsAndBuildings` | 消灭对方全部单位与建筑 | 全歼图 |
  | `noConstructionOrTech` | 无法建造且无科技（引擎有此枚举） | 特殊玩法 |
  | `requiredObjectives` | 需完成所有任务目标（引擎有此枚举） | 任务图 |

- 软件的 `winCondition` / `loseCondition` 下拉只列了**前 5 个**，
  后两个是下拉里没有的引擎合法值；下拉框可以直接输入，不会被强制改写。
  `requiredObjectives` 按枚举名推断要配合 `objective` 触发器使用，
  但这一点**没有实机验证过**，要用请先自己测一张小图。

- 游戏触发器类型只有 11 种（生成单位、检测单位、改资金、播报、移动、
  镜头、任务目标……），**没有"设置胜利"或"结束游戏"这个动作**。

所以结论是：**像"撑过第 3 波就赢""杀满 100 个兵判胜"这种自定义结束规则，
游戏本身就不支持用触发器实现，不只是这个软件写不了。** 能做到的只有：
选官方那 7 种判定之一 + 用 `objective` / `basic` 节点做任务文字和播报提示。
模板里的"通关播报"只是播报，不是胜利判定。

## ② 敌方 AI（team_1_info）

加一个对象（type 选「队伍配置」），名字 `team_1_info`：

| 属性 | 推荐值 | 说明 |
|---|---|---|
| `team` | `1` | 敌人队伍号，要和刷兵节点的 `team` 一致 |
| `ai` | `survival` | **关键**：让敌队用生存 AI 主动找玩家打 |
| `credits` | `120000` | 敌人资金，生存图给的都比较高 |
| `lockAiDifficulty` | `6` | 锁定 AI 难度 |

> 不配 `ai=survival`，刷出来的兵只会站着或游荡——这是最常见的"生存图不进攻"原因。

---

## ③ 出兵点（attack_point）

在地图上放点对象，右键节点图把类型改成「进攻点」。这个类型写盘时
**没有 type**，游戏靠对象名字 `attack_point` 识别（改类型时软件会自动改名）。
刷兵位置完全由对象坐标决定。

### 多个 attack_point = 每个点各刷一份（不是分摊）

放 N 个，官方波次的每一行就会在**每个点各刷一份**，
总兵量 ≈ 波次表数量 × 出兵点个数。本机真实图佐证：

| 地图 | attack_point 数 | survivalWaves 行数 |
|---|---|---|
| 海上堡垒 | 8 | 971 |
| 生存天方地圆 9p | 8 | 622 |
| 升级超难生存 10p | 10 | 226 |
| 9p 生存之战 | 4 | 50 |
| 地狱生存 / 抽奖生存 / 当前生存地图 | 1 | 若干 |

**别为了"多路"随手加 attack_point**——每加一个兵量翻倍。
当前 `生存地图.tmx` 只有 1 个，在 `(1532,2768)` ≈ 下方 87% 处，
这就是兵从下方刷出来的原因。

> 补充：铁锈战争**原版内置**生存（无自定义 `survivalWaves` 时）是另一套逻辑——
> 兵从地图外围、离玩家建筑最远的一边随机刷出，不依赖 attack_point。
> 自定义 `survivalWaves` + `attack_point` 才是地图作者可控的那套。

## ④ 波次编排

### 方案 A（推荐）：波次生成器 —— 保留官方倒计时

编辑器新增的 `waveGen` 类型，专门编排**原版生存波次表**。
游戏会显示官方 Wave 倒计时并按表刷兵。它只在**地图模式 = survival** 时
出现在类型下拉里。

操作步骤：

1. 在 `Triggers` 对象层放一个点对象，节点图选中它，类型改成**波次生成器**。
2. 右侧属性填三项：
   - **波次时间**：`0:10`（距开局 10 秒）或 `70s`，两种写法都行
   - **波次名称**：如 `第一波`，显示在倒计时旁
   - **刷兵列表**：`6 bugMelee,2 heavyTank`，也接受 `bugMelee*6` 写法
3. 从节点右上的橙色端口拖到下一波节点的入口端口，**串成一条单链**：
   第一波 → 第二波 → 第三波。
   - 右键点一个波次节点 →「**在其后插入一波**」可以接着往下加
   - 右键点连线可以删除
4. 保存时编辑器自动校验链条：必须恰好一个起点（第一波），
   每个节点最多一个下一波、最多一个入边，不能孤立、分叉、成环、
   指向不存在的节点。有问题会弹窗列出，可选返回修改。
5. 校验通过后按链顺序编译成原版 `survivalWaves` 写进 `map_info`：

   ```text
   +0:10 第一波 - 6 bugMelee,2 heavyTank
   +0:30 第二波 - 4 mechFlame,8 bugMelee
   +0:40 最终波 - 2 experimentalDropship,6 heavyTank
   ```

编排数据全部存在编辑器私有属性里（写进地图根属性 `rwmap_layout`），
游戏看不到，**不会报 `Key was not used`**；重开地图后节点和连线会自动恢复。

**播报 / 奖励怎么接**：`basic`（播报）、`changeCredits`（加钱）等触发器
用普通连线接到波次节点上，保存时记进该波次的 `rwmap_wave_link`，
重开地图会恢复成连好的线。同时保存会按波次累计时间生成一个隐藏的
`basic` 调度触发器（`delay=累计秒数s` + `alsoActivate=目标 id`），
游戏里到点就会真正触发这些播报 / 奖励。
注意：`attack_point` 是出兵点、不是触发器——游戏加载触发器时会按名字跳过它。
如果你把 `attack_point` 的类型设成 `unitAdd` 并写了「生成单位」（例如
`bugMeleeT31*100` 杀手虫），再从波次节点拉一条「波次关联」过去，保存时编辑器会
**自动在每个点旁边生成一份隐藏的同款影子刷兵触发器**（同坐标、同刷兵列表、
`team` 默认取 `ai=survival` 的队伍），并接到该波次的调度器上。这样 25 个点
各自的位置都会真的刷出单位；原对象仍叫 `attack_point`，官方波次照常使用它们。
影子触发器不显示在节点图 / 地图画布，私有标记也不会写进游戏属性。

> 用了波次生成器后，**普通触发器不要再单独放 `unitAdd` 刷兵节点**，否则原版
> 波次表和触发器会各刷一波。上面这种「`attack_point` + 波次关联」是例外：
> 它只是让出兵点额外刷一批指定单位。播报 / 奖励类触发器可以照常连。
>
> 另外提醒：官方波次每波只在 **一个随机** `attack_point` 刷兵（不是 25 个点
> 各刷一份）；想让每个点都刷，就用上面的影子刷兵机制。

### 方案 B：官方波次表节点（waveTable）

如果你想直接贴一大段现成的原版波次表（几百行的那种），用这个：
类型选「官方波次表」，在**波次表文本**属性里整段粘贴。这个节点
不在地图画布显示，但能在节点图里连线；保存时同步到 `map_info.survivalWaves`。
和方案 A 一样保留官方倒计时，只是编排方式从"每波一个节点"变成"一段文本"。

### 方案 C（旧）：unitAdd 触发器刷兵（无官方倒计时）

纯靠 `unitAdd` 触发器刷兵的旧做法，**没有官方倒计时**，保留供特殊需求参考。
连线由自定义属性里的 id 引用反推：

- `alsoActivate`：本节点激活时顺带激活谁（正向边，绿色）
- `activatedBy`：本节点由谁激活（反向边，蓝色）
- **只写一种**。两个都写会把一条连接画成两条线（一绿一蓝）。本模板统一只写 `alsoActivate`。

| 节点名 | type | id | 关键属性 | 作用 |
|---|---|---|---|---|
| ① 第1波刷兵 | `unitAdd` | `wave1` | `warmup=10s`、`team=1`、`spawnUnits=bugMelee*6,heavyTank*2`、`alsoActivate=wave1_msg,reward1,wave2` | 开局 10 秒刷第一波 |
| ① 播报：第1波 | `basic` | `wave1_msg` | `globalMessage`、`globalMessage_textColor=red` | 左上全局播报 |
| ① 奖励 +500 | `changeCredits` | `reward1` | `team=0`、`add=500` | 给玩家队发钱 |
| ② 第2波刷兵 | `unitAdd` | `wave2` | `warmup=30s`、`team=1`、`spawnUnits=mechFlame*4,bugMelee*8` | 第一波后 30 秒刷第二波 |
| ② 播报：第2波 | `basic` | `wave2_msg` | 同上 | 播报 |
| ② 奖励 +800 | `changeCredits` | `reward2` | `add=800` | 奖励 |
| ③ 最终波刷兵 | `unitAdd` | `wave3` | 被 wave2 激活、`warmup=40s`、`spawnUnits=experimentalDropship*2,heavyTank*6` | 最终波 |
| ③ 播报：最终波 | `basic` | `wave3_msg` | — | 播报 |
| ③ 奖励 +1200 | `changeCredits` | `reward3` | `add=1200` | 奖励 |
| 通关播报 | `basic` | `win_msg` | 被 wave3 激活、`globalMessage_textColor=yellow` | 撑过三波后播报（**只是播报**） |
| 地图规则说明 | `mapText` | `rules_text` | `text`、`textColor=yellow`、`textSize=12`、`showOnMap=true` | 地图内规则说明 |

```text
wave1 (刷兵)
├─ wave1_msg (播报)
├─ reward1   (+500)
└─ wave2 (刷兵, warmup 30s)
   ├─ wave2_msg
   ├─ reward2
   └─ wave3 (刷兵, warmup 40s)
      ├─ wave3_msg
      ├─ reward3
      └─ win_msg (通关播报)
```

`unitAdd.warmup` 是"被激活后多久生效"，所以
`wave1.alsoActivate=wave2` + `wave2.warmup=30s` = 第一波刷出后 30 秒刷第二波。

## 参数速查

- **时间**：一律带 `s`（`10s`、`0.5s`），波次生成器也接受 `分:秒`（`0:10`）
- **`spawnUnits`**：`单位名*数量,单位名*数量`，可带括号参数，
  如 `mechFlame(spawnChance=0.04,maxSpawnLimit=1)`
- **`randomUnits`**：`单位名:权重#数量`，如 `heavyTank:3#4,tank:1`；
  导出时折算成链式 `spawnChance`
- **`team`**：敌人队和玩家队按地图实际改；`0`/`1` 常用，`-2`/`none` 为中立
- **`rwmap_node_pos="x,y"`**：本编辑器私有的节点图布局属性，游戏忽略
- **进攻路线可选**：`point`（坐标锚点）+ `move`（`target=point名`、`team=1`、`delay`）
  是可选增强，只有大型生存图才配几百条；简单图不配也能玩

## 常见坑

1. **双刷兵**：用了波次生成器 / 官方波次表，就别再放 `unitAdd` 刷兵节点。
2. **不进攻**：`team_1_info.ai` 必须是 `survival`，否则兵站着不动。
3. **兵量翻倍**：`attack_point` 每多一个，每波兵就多刷一份。
4. **私有属性泄漏**：节点编排数据只走 `rwmap_layout` 根属性，
   不能写成对象的普通属性，否则游戏报 `Key was not used`。
5. **刷兵点位置**：由 `attack_point` 对象坐标决定，拖到哪兵就从哪冒。
6. **胜利条件**：`winCondition` / `loseCondition` 是官方枚举，
   没有"第 N 波后胜利"这种自定义规则（详见上文）。
7. **软件修改需重启**：改了源码后要重启编辑器，新类型 / 新菜单才会出现。
8. **撤销**：全部操作都进撤销栈，Ctrl+Z 可整批撤回。
9. **出兵点被改名会闪退**：游戏 `TriggerEngine` 只认名字恰好是 `attack_point`
   的对象。用整合体批量改名字把出兵点改成「刷虫子」之类的，游戏里没有任何
   出兵点，第一波 `updateWaveSpawnPoint()` 会空列表越界（`rwpp-log.txt` 里是
   `Activating wave → min>max → IndexOutOfBoundsException`）直接闪退。
   保存生存图时软件会自动把这些对象改回 `attack_point` 并在状态栏提示。
   同理，整合体同步编辑不会覆盖各成员的自定义 `id`（25 个点共用一个 id 会让
   触发链只命中第一个）。
