## 0. 一张图看懂：属性和指令放在哪

```
xxx.tmx  (Tiled 地图)
├── <map width height tilewidth=20 tileheight=20 ...>   ← ① 地图根属性
│   └── <properties>                                    ← 地图自定义属性（多数是作者备注）
├── <tileset firstgid name source ...>                  ← 图集
│   └── <tile id><properties>                           ← ② 图块属性：water / cliff / unit / team ...
├── <layer name="Ground|Items|Units|set">               ← ③ 瓦片层（按名字识别，见第 2 节）
└── <objectgroup name="Triggers">                       ← 指令层
    └── <object name type x y width height>
        └── <properties>                                ← ④ 触发器属性 = 指令参数
```

游戏实际只关心 ②③④；`<map>` 的宽高和瓦片尺寸也必须对。`Triggers` 对象是矩形只是「载体」，**位置和大小大多没有意义**（少数如 `point` / `camera_start` / `unitDetect` 用得到坐标）。

## 1. 地图文件级属性

| 位置 | 键 | 实测/约定值 | 说明 |
| --- | --- | --- | --- |
| `<map>` 根 | `width` / `height` | 150、160、200、300、500、600 | 格数，本机出现过 13 / 14 种尺寸 |
| `<map>` 根 | `tilewidth` / `tileheight` | **20 / 20**（24 张图全一致） | 官方图集就是 20×20，改了会错位 |
| `<map>` 根 | `orientation` | `orthogonal` | 正交 |
| `<map>` 根 | `renderorder` | `right-down` | |
| `<map>` 根 | `version` / `tiledversion` / `nextobjectid` / `nextlayerid` / `infinite` | Tiled 自用 | 游戏不读，写回时须保真保留 |
| 图层编码 | `Tile Layer Format` | **Base64 (gzip compressed)** | Tiled 导出设置；格式不对游戏读不出图层 |
| 地图 `<properties>` | `tag`=`RW`、`fill`、`sw1`…`sw6`、`author` | 社区图自定义 | **不是游戏字段**，是作者/工具留的备注；本机 11~15 张图出现，官方示例没有 |
| 图集 `<properties>` | `embedded_png` | 图片 base64 | 把自定义图集图片嵌进 `.tsx`，分发单个 `.tmx` 时用；游戏内可见，Tiled 里仍走本地路径 |

## 2. 图层约定（游戏按层名识别，大小写敏感）

| 层名 | 类型 | 游戏用途 | 官方 readme 原文要点 | 实测 |
| --- | --- | --- | --- | --- |
| `Ground` | 瓦片层 | 地形 | 地形瓦片放这层，**必须填满**；用自动映射时不要手改，会被覆盖 | 23 张 |
| `Items` | 瓦片层 | 资源池 / 树 / 石头 | 资源池**必须**放这层才生效；**禁止放地形瓦片**，否则寻路失效 | 23 张 |
| `Units` | 瓦片层 | 起始单位、建筑 | 只放单位；其它东西放这层会被忽略 | 18 张 |
| `Triggers` | **对象层** | 地图设置、玩家统计、事件 | 触发器都在这层 | 15 张（另有 4 张写成小写 `triggers`） |
| `set` | 瓦片层 | **游戏完全忽略** | 只给 Tiled 自动映射当输入，应该在这层画基础地形标记 | 3 张 `set` + 3 张 `Set` |
| `UnitObjects` | 对象层 | 对象形式的单位 | 对象上写 `unit` + `team` | 8 张 |
| `PathingOverride` | 瓦片层 | 寻路覆盖 | 社区资料提到，本机官方图零命中 | 0 张（项目按「只读保真」处理） |

> 项目对应：`config/layer_rules.json` 定义 `order: Ground, Items, Units, Triggers, set`，未知层策略 `readonly_preserve`，`set` 默认隐藏。
> 注意社区图里出现 `triggers`（小写）、`Set`（首字母大写）、`提示`、`position` 等自定义对象层，游戏只认标准名。

## 4. 单位与队伍

- **单位名不是数字 ID**，是 raw name 字符串：`builder`、`tank`、`commandCenter`、`extractorT1`、`bugMeleeT31`、`mechLaser` …
- 权威来源顺序（项目 `rwmap/rw/units.py`）：`units.tsx` 的 `<tile><property name="unit">` → `assets/units/**/*.ini` 的 `[core] name:` → `.rwmod` 内 ini；`displayText` 只作显示名。
- 起始单位放在 `Units` 瓦片层，或者 `UnitObjects` 对象层（写 `unit` + `team`）。
- **`team` 取值**（实测）：`0`~`14` 为队伍编号；`-1`（2615 次）、`-2`（2603 次）、`none`（114 次）在社区图里大量出现，通常表示中立/任意/无归属一类语义，但**官方 readme 未明确定义**，项目配置把 `team=-2` 列为 `unverified`，用之前建议实测确认。
- 图集里白色数字格子是指挥中心；摆单位时与其它单位/资源池留 1 格间隔，避免显示异常。

指令由 `Triggers` 对象层里 `<object>` 的 **`type`** 决定；少数固定信息用 **`name`**（`map_info` / `team_0_info` / `camera_start`）。下表按本机实测频次排序。

### 5.1 按 `type` 的指令

| type | 实测对象数 | 作用 | 核心参数 |
| --- | --- | --- | --- |
| `unitAdd` | 8997 | 刷兵 / 生成单位 | `spawnUnits`、`team`、`warmup`、`repeatDelay` |
| `unitDetect` | 3008 | 检测区域内单位数量并触发 | `unitType`、`minUnits`、`maxUnits`、`team`、`alsoActivate` |
| `mapText` | 1451 | 地图上显示文字 | `text`、`textColor`、`textSize`、`showOnMap` |
| `unitRemove` | 1062 | 移除单位 | `team`、`activatedBy`、`resetActivationAfter` |
| `changeCredits` | 828 | 改某队资金 | `add`（增量）/ `set`（设值）、`team` |
| `move` | 306 | 让某队单位移动到指定点 | `target`（指向 `point` 对象的 name）、`team`、`delay` |
| `basic` | 230 | 通用事件 / 全局播报 | `globalMessage` + 调度参数、`id` |
| `point` | 212 | 坐标锚点，供 `move` 的 `target` 引用 | 只需设置对象 `name` |
| `team_info` | 17 | 队伍配置 | `team`、`credits`、`allyGroup`、`ai`、`lockAiDifficulty` |

### 5.2 按 `name` 的固定信息对象（官方/教程）

| name | 关键属性 | 取值与说明 |
| --- | --- | --- |
| `map_info` | `type` | `skirmish`（遭遇战）/ `mission` / `survival` / `challenge` / `endless`；不写可能没有胜利提示 |
| | `introText` | 开局简报文字，`\n` 换行 |

## 6. 通用调度参数（几乎所有 type 都能用）

| 属性 | 实测次数 | 格式 | 作用 |
| --- | --- | --- | --- |
| `team` | 13000+ | 数字 / `-1` / `-2` / `none` | 作用队伍 |
| `warmup` | 7454 | `30s` / `0.1s` / `150s` | 开局（或被触发后）多久生效 |
| `resetActivationAfter` | 7236 | `0.5s` / `300s` | 触发后多久复位，可再次触发 |
| `deactivatedBy` | 6305 | 逗号分隔的 `id`，如 `A,Q,W,C` | 这些 id 激活时禁用本触发 |
| `activatedBy` | 5212 | 逗号分隔的 `id` | 由哪些触发/开关激活 |
| `repeatDelay` | 2536 | `60s` / `260s` | 重复执行间隔 |
| `delay` | 280+ | `39s` / `0.1s` | 单次延迟 |
| `allToActivate` | 341 | `true` / `false` | `activatedBy` 里是否要全部满足才激活 |
| `alsoActivate` | 293 | 逗号分隔的 `id` | 本触发激活时顺带激活谁 |
| `id` | 2275 | 字符串或数字 | 本触发的标识，供 `activatedBy` / `alsoActivate` / `target` 引用 |
| `whenActivatedIds` | 30 | id 列表 | 激活后要通知的 id（社区图常错拼成 `whenActivatedlds`） |
| `globalMessage` | 548 | 任意文本 | 左上角全局播报 |
| `globalMessage_delayPerChar` | 486 | `0.1s` / `0.2s` / `slow` | 逐字显示速度 |
| `globalMessage_textColor` | 484 | `red` / `#00FFFF` | 播报颜色 |
| `text` / `textColor` / `textSize` | 1197 / 1196 / 1132 | 文本 / 颜色 / 字号(8~16) | `mapText` 用 |
| `showOnMap` | 12 | `true` | 小地图/地图上可见 |
| `target` | 306 | `point` 对象名 | `move` 的目标 |
| `add` / `set` | 663 / 85 | 整数（可负） | `changeCredits` 增量 / 设值 |
| `minUnits` / `maxUnits` | 2364 / 528 | 整数 | `unitDetect` 数量区间 |

**值格式约定**
- 时间：数字 + `s`，支持小数（`0.02s`）；实测 18543 个时间值里 99% 以 `s` 结尾。`globalMessage_delayPerChar` 另有 `slow`。
- 布尔：小写字符串 `true` / `false`。
- 颜色：英文 `red / yellow / green / blue / white / purple`，或 `#RRGGBB`（`#87CEFA`、`#CCBBFF`、`#00FFFF` 等）。
- 列表：英文逗号分隔，无空格（`A,Q,W,C,E`；`heavyTank*10,bugMelee*6`）。
- id：可以是数字（`3`、`21`）也可以是自定义字符串（`jcroom1`、`shibai4`、`vote_timeout`）。

## 7. `spawnUnits` 语法（刷兵参数）

```
spawnUnits = heavyTank*10, builder*2, bugMeleeT31*6
             mechFlame(spawnChance=0.04,maxSpawnLimit=1), turret(offsetRandomX=0,offsetRandomY=80,falling=true)
```

- 逗号分隔多个单位；`单位名*N` 一次生成 N 个。
- 单位名后可跟 `(参数=值,参数=值…)`，本机 9900 个 `spawnUnits` 里 1528 个带括号参数（社区高级玩法，官方 readme 未列）。

| 内联参数 | 实测次数 | 作用（按命名推断 / 社区用法） |
| --- | --- | --- |
| `spawnChance` | 1697 | 生成概率（0~1） |
| `maxSpawnLimit` | 1692 | 该单位生成数量上限 |
| `offsetRandomX` / `offsetRandomY` | 1077 / 1054 | 落点随机偏移 |
| `falling` | 953 | 从空中掉落入场 |
| `offsetHeight` | 194 | 生成高度（配合 falling） |
| `offsetRandomXY` | 190 | X/Y 一起随机偏移 |
| `techLevel` | 112 | 科技等级 |
| `neutralTeam` | 60 | 中立队伍 |
| `offsetDir` | 32 | 朝向偏移 |
| `gridAlign` | 17 | 对齐网格 |
| `skipIfOverlapping` | 1 | 重叠时跳过生成 |

## 8. 自动映射（`rules.txt`）相关属性

- `mods/maps/rules.txt` 只有三行：`./rules/ruleset1.tmx`、`ruleset2.tmx`、`ruleset3.tmx`。
- 规则图的 `<properties>`：`AutomappingRadius` = `2`、`DeleteTiles` = `1`（本机实测各 2 次）。前者决定重算窗口外扩格数，后者决定重算前是否清旧输出。
- 规则图里的**层命名约定**：`input_set` / `inputnot_set_decoration`（条件）、`output_Ground` / `output_Items` / `output1_Ground` 等（输出变体）、`regions` / `ruleRegions`（规则区域）、老式 `rule_Ground` / `ruleSet`。
- 规则图的 tile 属性直接用第 3 节的图块属性（`cliff-soft` 108、`water` 64、`cliff` 48、`large-rock` 44 …）作为条件/输出标记。
- 编辑器里对应实现：`rwmap/rw/automapping.py` → `compute()`（局部窗口 + `reset_base` + `rule.order` 仲裁），`rwmap/app/main_window.py` 的 `绘制时自动地图` 开关。过渡瓦片 gid（如 824）全部来自规则图 `output_Ground`，项目里没有手写岸线算法。

## 9. 易错拼写与坑（实测踩过的）

| 错误写法 | 正确写法 | 说明 |
| --- | --- | --- |
| `mainBuilings` | `mainBuildings` | **官方 `example_mission.tmx` 自己就拼错了**，别照抄 |
| `whenActivatedlds` | `whenActivatedIds` | 小写 `l` 冒充 `I`，本机 210 次；社区图高频错 |
| `activetedBy` | `activatedBy` | 52 次 |
| `loseConditions` | `loseCondition` | 复数形式，7 次 |
| `skimish` | `skirmish` | 2 次 |
| `large-clift` | `large-cliff` | 6 次；项目 `property_aliases.json` 已做归一 |
| ` cliff-soft` | `cliff-soft` | 前导空格，24 次，属性名带空格会失效 |
| `unutAdd` / `unitadd` / `unitunitAddAdd` | `unitAdd` | type 大小写/重复拼写错误，共 7 次 |
| `mapTetx` / `maptText` | `mapText` | 共 2 次 |
| `Set` / `triggers` | `set` / `Triggers` | 层名大小写，游戏按标准名识别 |
| `loseCondition` 与 `winCondition` 混用 | 分开写 | 生存图常用 `loseCondition`，遭遇战用 `winCondition` |

其它坑：
- `Ground` 层必须填满；资源池必须整块 3×3 放在 `Items`。
- `set` 层游戏忽略，只在 Tiled 自动映射里当输入；别把最终地形画在这层。
- `Triggers` 是**对象层**不是瓦片层；对象矩形位置大多无意义，但 `point` / `camera_start` / `unitDetect` 要用坐标。
- 自定义图集要嵌 `embedded_png`，否则分发地图会丢图；导出图层格式必须是 Base64 gzip。
- `team=-1` / `-2` / `none` 语义未验证，别在关键逻辑里依赖。
- 本机 30 个 `.tmx` 里 `爱琴海海战（10p）.tmx` 不是有效 XML（首字符非 `<`），统计时被跳过；遇到类似文件先确认格式。

| `rwmap/widgets/triggers_dock.py` | 对象语义树，可编辑名称/类型/坐标/属性 | 加属性下拉建议、错拼告警、时间/颜色格式校验 |

## 11. 做一张最小可运行遭遇战图

1. 新建正交地图，`tilewidth/tileheight = 20`，尺寸按需要（如 160×160），图层编码 **Base64 (gzip)**。
2. 建 4 层：`Ground`（用图集铺满地形）、`Items`（资源池/树）、`Units`（起始单位）、`Triggers`（对象层）；可选 `set` 供自动映射。
3. `Triggers` 里放一个矩形对象，`name = map_info`，加属性：
   `type=skirmish`、`introText=…`、`fog=map`、`winCondition=allBuildings`。
4. 每个队伍放一个 `team_#_info` 对象（`type=team_info`），写 `team=0`、`credits=120000`；`team=1` 同理。
5. 需要刷兵就加 `type=unitAdd` 的对象：`spawnUnits=tank*5`、`team=0`、`warmup=30s`；配合 `type=unitDetect`（`unitType=tank, minUnits=1`）与 `id` / `activatedBy` 做联动。
6. 同目录放 `xxx_map.png` 缩略图（游戏内 160×160，创意工坊 200×200）。
7. 存到 `mods/maps/`，游戏里 单人游戏 → 自定义地图 测试。
